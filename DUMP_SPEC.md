## Freshness contract (what the loop tracks)
- `dump_manifest.json`: `staged_at` UTC, row counts per file, `jmq_inputs_ready` (true once TEST-JMQ generations exist), `pending` list (e.g. ["s3_generations/L1", "judging inputs"]).
- `tick_summary.py` prints: staged_at age, counts, jmq readiness. Loop prompt requires it every tick.
- Push on every material change (new stage done, new freeze, new parquet), not on a timer — timer is for ticks, content triggers pushes.

## Local consumption
- JMQ: run four resumable `local_jmq.py` shards against the dump feed through the authenticated OpenCode CLI; `src/watchdog_local.py --repair-jmq` merges only parseable verdicts. Then run `python src/jmq_stats.py` for 10k bootstrap CIs, exact paired label-swap tests, Holm correction, and figure data before pushing the outputs back into the dump repo.
- Stats/figures/paper: `runs.jsonl` + `metrics/` + `figures/data/` + `manifest.yaml` are sufficient (all numbers are precomputed on VAST; local only bootstraps/plots/writes).
- MMD additions are pulled into a separate `hf_incoming/<commit>` directory, checked against `mmd_hf_sha256sums.txt`, and promoted only after all 20 hashes pass. Never use the MMD pull to overwrite the verified core mirror.
- Weights never needed locally. Tokenizers resolve from SHAs.
